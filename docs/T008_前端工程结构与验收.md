## 实现边界

依据原始开发计划 T008、架构说明书 3.3 Monorepo 及阶段00 T005。仅拆分前端工程；未修改本轮后端 API、数据库或业务角色，未升级 Java/Spring Boot。T009 及以后按各自规范另轮展开。

- `apps/web`：用户端，入口 `/`。
- `apps/admin`：独立 Vue/Vite 后台，入口 `/admin/`；迁入现有后台页面，`/users` 可直接刷新。仪表盘与用户管理仍沿用现有组合页面，分开展示属于 T013，未提前标为完成。
- `packages/ui`：Vue 版 shadcn-vue/Reka 组件、CSS 令牌、主题存取及外观设置，已移除原 React UI 模板。内部没有 web 的 `@/` 别名。
- `packages/session`：Axios 请求、当前标签页 sessionStorage 访问令牌、单飞刷新、退出和导航白名单。web 原 `lib/auth`、`utils/request`、`lib/theme` 保留兼容导出。
- 两个应用只依赖共享包，不导入另一应用的页面。共享包直接导出源码，不要求先生成其构建产物。
- 两个应用的 API 基址固定为同源 `/api`。旧本机 `VITE_API_BASE_URL` 不再生效；开发时通过 `API_PROXY_TARGET` 配置后端代理。
- 跨应用使用同标签页整页导航，共享同源 sessionStorage 与刷新 Cookie。未扩大到跨标签页同步或持久化 access token。

## 启动和构建

从 `frontend` 运行：

| 操作 | 用户端 | 后台 |
|---|---|---|
| 开发 | `pnpm dev:web` | `pnpm dev:admin` |
| 类型检查 | `pnpm check:web` | `pnpm check:admin` |
| 生产构建 | `pnpm build:web` | `pnpm build:admin` |

`pnpm dev` 同时启动两个应用。默认 web 3000、admin 3001；浏览器统一访问 web 的来源，web 将 `/admin` 边界下的请求（含 HMR）代理到 admin。后台绑定 127.0.0.1，避免 IPv6 默认监听导致代理 502。不要通过 3001 直接登录。

生产 Dockerfile 分别构建并复制 web/dist、admin/dist；Nginx 分别回退至 `/index.html` 与 `/admin/index.html`，`/admin` 使用相对 308 跳转。缺失 JS/CSS 返回 404。Turborepo 按本机 2.11.13 附带文档配置 Vite 的 `dist/**` 输出。

## 登录与访问行为

后台守卫先检查令牌，再请求 `/v1/me`；普通用户进入后台显示 `/admin/404`，不加载管理数据。API 权限仍由原服务端负责。网络故障进入可重试的不可用页。

未登录后台跳到用户端登录并保留 `returnTo`。白名单仅允许当前实现的 `/app`、空间/目录 ID 路径、`/admin`、`/admin/users`；拒绝外部地址、协议相对地址、反斜线、编码路径、控制字符、未知页面及跳转循环。登录后台使用整页导航。
