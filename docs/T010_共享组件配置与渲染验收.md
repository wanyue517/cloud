# T010 共享组件配置与渲染验收

日期：2026-11-25。状态：**已验收**。分支：`codex`，`main`保持`91d0f62`。

## 范围与复用

原计划T010要求Tailwind CSS、shadcn-vue基础配置，验收为按钮、输入和弹窗可渲染。沿用两个应用的Tailwind Vite插件、共享CSS入口、显式共享包源码扫描和已有Vue/Reka组件；没有重建UI库或新增组件依赖。

按[官方components.json说明](https://www.shadcn-vue.com/docs/components-json)核对配置：CLI使用aliases与TypeScript paths定位组件和工具，Tailwind v4的config字段可以留空。原配置将npm模块cn作为工具文件路径，且共享组件目录缺少对应路径映射。

本轮修补：
- 三份components.json的ui别名统一到`@repo/ui/components`，工具别名到`@repo/ui/lib/utils`；应用的CSS配置指向共享样式源。
- 在共享包和两个应用的TypeScript配置中补上相应paths，生成目录能映射到packages/ui/src。
- 共享包提供lib/utils入口，现有基础组件统一从该入口使用cn；web原工具路径保留兼容，admin提供同样的兼容入口。
- 补上组件barrel、Vue深层文件和工具的包导出；保留已有`@repo/ui/button`等导入，不引入应用间源码依赖。
- DialogContent、DialogScrollContent、DialogFooter和SheetContent的默认关闭文案统一为中文。

本轮核查的是当前手工维护组件的配置、导出与运行时渲染，没有运行CLI add覆盖定制组件，也不声称验证过第三方registry写入流程。后续新增基础组件集中维护在packages/ui。
