# 对象存储分片直传

后台「存储管理 → 编辑 S3 实例 → 文件上传方式」可以选择：

- 后端中转：客户端分片上传至应用服务器，再由服务器流式写入对象存储。
- 对象存储直传：客户端使用短期签名地址直接将分片上传至对象存储。
- 自动选择：达到大小阈值的文件直传，其他文件中转。默认阈值 100MiB。

已有实例迁移后保持中转，不自动切换。LOCAL、DB 实例仅支持中转。普通文件上传在 PC 与移动端均接入；文件替换及系统资源上传继续使用原接口。

## 开启前配置

1. 部署包含 V20 迁移的后端及新版前端。迁移新增实例和任务上传配置，并允许未知的整文件 SHA-256 为 NULL。
2. 确认用户设备可访问 S3 API Endpoint。R2 使用账户的 S3 Endpoint，不能用只读公共资源域名替代。
3. 给存储桶配置 CORS。允许实际站点及原生客户端的来源、PUT 方法、Content-Type 请求头。不要将应用 JWT 或私有区令牌发送给对象存储。
4. 配置未完成 Multipart 上传的生命周期清理作为崩溃后的兜底。应用也会在取消和任务过期时调用 AbortMultipartUpload。
5. 首次建议使用测试实例与小范围用户验证，再切换正式实例。

R2 CORS 示例（替换站点域名；原生客户端来源需要按实际 WebView 配置补充）：

```json
[
  {
    "AllowedOrigins": ["https://cloud.example.com"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

当前客户端不依赖浏览器读 ETag：后端使用 ListParts 获取可信的分片列表与 ETag。CORS 和签名配置仍必须正确。后台「测试连接」只验证服务器到存储的连通性，不能替代用户浏览器的直传验证。

## 配置与行为

默认分片 16MiB、并发 3、签名有效期 900 秒。分片大小可设 5–64MiB，并发 1–6，有效期 60–3600 秒。每次分片重试重新签名，暂停后继续会从存储端查询已完成分片。零字节文件使用中转。

上传模式、分片大小、并发和有效期在创建任务时固定。修改实例策略影响新任务，不会更改已有任务。凭据、桶和 Endpoint 不应在有活动任务时变更。

失败默认保留任务并提示重试。管理员可选择「切换中转并重新上传」：先清理直传分片，再将同一任务切为中转，进度归零并显示重传提示。若存储端本身不可达，回退清理也可能失败，应稍后重试。

数据上传完毕后，后端异步校验分片编号、各分片大小及最终对象长度，再重新校验目录权限、文件规则和配额，幂等提交文件记录。正在执行完成处理的直传任务暂不能取消。对象已合并但元数据提交失败时保留对象，重试无需重传；取消或过期时清理。

Multipart ETag 不等于完整文件 SHA-256。直传完成时将整文件哈希保存为未知，不信任客户端声明的哈希，也不将其用于秒传复用；已有可信哈希的文件仍可命中原有用户级秒传。当前完成验证不执行内容扫描或整文件 SHA-256 重算。

## 方式对比

| 项目 | 后端中转 | 对象存储直传 |
| --- | --- | --- |
| 应用服务器资源 | 使用带宽、连接及临时磁盘，流式处理避免整文件入堆 | 文件主体绕过服务器，仅处理控制请求 |
| 网络要求 | 用户可访问应用即可 | 用户也需能访问对象存储 Endpoint |
| 大文件完成 | 仍需服务器转存 | 存储端合并分片，无服务器转存 |
| 部署复杂度 | 较低 | 需要 CORS、Multipart 权限和清理策略 |
| 内容校验 | 可在后端读取时计算整文件哈希 | 需存储端校验或独立后处理 |

直传只改变上传路径，缩略图和预览的后端资源限制仍然适用。

## 本地验证

- `python scripts/verify-upload-completion.py`：仅使用本地配置创建并删除独立测试库，验证 V20 迁移、中转回归和直传元数据流程。
- `mvn -B -pl cloud-api -am -Dtest=S3MultipartTest -Dsurefire.failIfNoSpecifiedTests=false test`：在 backend 目录运行本地 HTTP 协议验证。
- `pnpm --filter @repo/drive-core test`：在 frontend 目录验证续传、并发、重试刷新签名、取消与回退。
- `scripts/verify-direct-upload-ui.py`：配合本地管理端 Vite 服务运行，使用模拟 API 验证配置保存及响应式布局，不写真实存储实例。

协议与集成测试使用本地 HTTP 服务或模拟 S3。上线前仍需在目标 R2/MinIO 实例验证实际权限、CORS、网络和大文件传输。
