## 二、从这批文档提取的统一结论

1. **产品边界**：P0 为可运行的个人网盘闭环；P1 补全共享、版本、全文检索和完整后台；P2 为去重、迁移等增强。
2. **空间**：个人/共享空间在一个空间列表混排；私密空间单独入口；共享文件夹是虚拟共享根，不改变原目录。
3. **文件核心模型**：FileNode → FileVersion → BlobObject → StorageProfile；重命名和移动不会触发物理文件移动。
4. **权限**：有效授权由后端统一裁定；共享权限继承到授权根后代，但不得访问上级/兄弟目录。
5. **文件树**：树行单击切换当前目录、展开箭头独立展开、列表双击进入/预览；大树按需加载与虚拟化。
6. **接口**：`/api/v1`，`code/msg/data/traceId`，BIGINT ID 在 JSON 和前端始终为字符串，错误同时使用正确 HTTP 状态。

## 三、需要项目所有者评审的少量策略

以下不影响本文档作为开发初稿，但建议在 T008 开始前确定并在相应文档中修改：

1. **空间同名**：默认建议允许同用户存在同名空间，用图标/辅助标识区分；也可改为同所有者唯一。
2. **VIEWER 下载与版本查看**：默认允许，所有者可通过共享策略限制；如果希望查看者默认不可下载，应修改权限矩阵。
3. **跨空间移动**：同所有者可移动；跨所有者空间默认禁止直接移动、建议复制。是否允许受邀编辑者将自身上传文件移出，需要单独规则。
4. **默认认证形式**：T007 展示 Bearer Access Token；具体是否采用内存 Access Token + HttpOnly Refresh Cookie，在 T021/T022 锁定，不影响响应/ID 规范。
5. **版本清理策略**：数量包括当前版本，物理清理延迟执行；P1 上线前还需确定恢复保护期和容量配额详情。
